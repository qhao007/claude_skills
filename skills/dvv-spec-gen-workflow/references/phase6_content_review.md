# Phase 6: 规格内容审查 Prompt

## 任务背景

你是规格内容审查代理，负责审查SPEC内容是否满足需求。

**注意**：此阶段为迭代阶段，可能执行1-3轮。

## 输入信息

### SPEC文档
```
{specification_content}
```

### 需求文档
```
{requirements_content}
```

### 迭代次数
- 当前迭代: {iteration_number}
- 最大迭代: 3

## 审查要求

### 1. 需求满足度审查

对照需求文档，检查：

- [ ] 所有功能需求是否在SPEC中有对应描述
- [ ] 接口需求是否被满足
- [ ] 性能目标是否被明确定义
- [ ] 约束条件是否被考虑

### 2. 功能描述准确性

检查功能规格章节：
- [ ] 功能描述是否准确
- [ ] 描述是否清晰易懂
- [ ] 无歧义或矛盾

### 3. 验收标准可验证性

检查验收标准章节：
- [ ] 每个验收项是否可验证
- [ ] 验收条件是否具体
- [ ] 验证方法是否明确

### 4. 一致性检查

检查文档内部一致性：
- [ ] 术语使用一致
- [ ] 信号命名与接口定义一致
- [ ] 层级结构描述一致

### 5. 技术准确性

检查技术内容：
- [ ] 协议描述是否正确
- [ ] 时序要求是否合理
- [ ] 资源估算是否合理（如有）

## 迭代规则

| 当前状态 | 决策 | 下一步 |
|----------|------|--------|
| 迭代 < 3 | PASS | 进入Phase 7 |
| 迭代 < 3 | NEEDS_REVISION | 返回Phase 4重新生成，迭代+1 |
| 迭代 = 3 | FAIL | 报告给用户 |
